# Behavior verification

These scenarios exercise routing, continuity, authority and Matt's methods. They are inputs and observable expectations, not a fixed work lifecycle. Structural validation does not execute them.

For a behavior run, give a fresh agent the installed suite, only the scenario's starting context, and a disposable project. Record its actual job choices, questions, edits, artifact paths and verification statements. Score each expectation from the trace and resulting files. Keep traces under the selected session's `evidence/`, identifying whether the run used real tools, a dry decision walkthrough or an independent source review. Never label a walkthrough an end-to-end workflow run.

Run the new source only. No comparison to discarded Hyper is required. Use sequential evaluation when independent agents are unavailable and disclose the reduced independence. Host menu metadata and filesystem installation checks are separate from live host discovery.
